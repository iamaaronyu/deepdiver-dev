# 商务报告界面与研究深度改进

日期：2026-10-22。依据用户对观感与研究深度的反馈实施，视觉方向由用户选择为“偏商务报告”。本次为阶段 4 后的产品改进，不宣称已完成阶段 5 十题质量评测。

## 问题与改进

原界面使用大量小字号、淡色文字和后台统计卡片，报告缺少阅读导航。现采用深蓝导航、暖白纸面、克制的金色强调，提高正文与辅助文字可读性，减少统计卡片分割；报告有独立目录、章节层级、页内证据跳转及打印样式，保留桌面与手机适配。

原研究每轮最多提取 4 条主张，主要输出摘录清单；一些初始主张通过后便停止，缺少针对原问题的比较、解释与综合判断。现在：

- 工作台默认深度研究，标准模式仍可选。深度模式默认最多 3 轮、600 秒、12 次搜索、每次 5 个候选来源，美元上限仍为 0.25；用户可以修改上限。
- 深度规划覆盖互补角度：机制与事实、替代方案与取舍、边界与反证；补充查询携带已有主张及前轮查询，寻找缺口与独立视角。
- 深度模式在允许至少 2 轮时，首轮主张通过也会补查第二视角；预算或时限先到时仍停止，显式设置单轮时不会越界。
- 来源上下文先跨域分配，再按相关性填充，最多 12 页；每轮最多 8 条候选主张，全任务最多 16 条。补查可为同一主张增加证据。
- 新增综合分析成文，依据已取得且获支持/部分支持的主张，组织核心判断、主题分析、决策启示和未回答的问题。每个分析段落必须引用服务器已知的主张 ID，服务器生成证据链接，不让模型生成来源 URL。未知或不合格引用使整份综合分析被拒绝，退回明确标注的证据报告。
- 逐字摘录、独立核验、跨域与时效性检查继续保留；部分支持会在分析引用旁明确显示，不因成文而升级为事实认证。没有合格证据时不调用分析成文。
- 深度模式单次模型调用最长 180 秒，并被任务总时限进一步约束；普通模式与单轮 API 继续使用原配置超时。所有调用仍受 token/请求/费用上限约束，无自动付费重试。
- 报告保留原始证据附录，费用与用量改为可阅读文字，完整运行数据继续存在数据库/API 中。

## 关键文件

`apps/web/app/page.tsx`、`task/page.tsx`、`globals.css`、`components/shell.tsx`、`lib/api.ts`；`deepdive/agents/planner.py`、`researcher.py`、新增 `synthesizer.py`、`writer.py`；`deepdive/orchestration/models.py`、`controller.py`、`deepdive/providers/llm.py`。新增深度流程与分析引用测试，扩展浏览器模式切换及目录/引用跳转测试。

未增加第三方依赖或修改数据库 Schema。旧任务、旧报告版本及失败记录保留；新研究逻辑适用于新创建任务，已有报告不会自动重跑或消耗模型费用。

离线检查覆盖深度补查、单轮上限、未知引用拒绝、不合格证据排除、分析失败回退与深度调用超时边界；浏览器检查覆盖模式提交、报告目录及页内证据跳转，并保留安全 Markdown 和移动布局检查。真实样例为 Python TaskGroup 与 gather 的异常、取消、结果收集和迁移边界比较。

首次真实任务 `bc2e51f6322543f2832262bfc02ab689` 取得 10 个有效正文来源，但证据提取触发原先单次模型 60 秒超时，状态 FAILED；该失败未计通过。记录在 `data/business-review/result.json`，保守预留金额 0.0372744 USD，用量不完整，实际费用不可可靠估算。随后显式调整深度调用时限并运行新的受限研究，未删除失败或自动重试原任务。

## 局限

综合分析的引用 ID 校验确保引用可追溯，不等于逐句证明分析没有语义扩张；仍需结合原文复核。跨语言转述和同域名重要主张可能被保守标记为部分支持。现有远端 Fetch 重定向链边界不变。单题真实通过不能证明一般研究质量，十题固定评测与策略比较仍待开展。
